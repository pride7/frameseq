Write slides in code. Shape them on screen.

Why FrameSeq

Stop choosing between a slide app and a text file.

Slide apps are visual but opaque. Markdown slides are plain text but run out of layout. FrameSeq keeps the text file and gives you the canvas back.

Coming from a slide app

The catchEvery change is a click in a binary file, so your slides are hard to diff, review, or regenerate.

With FrameSeqA .slides.ts file that lives in Git beside your code, and a Studio for the moments you want to drag things.

Coming from Markdown slides

The catchWriting is quick until a slide needs a custom layout or a precise position; from there it is mostly HTML and CSS.

With FrameSeqSplit, grid, named regions, canvas, shapes, and connectors are commands. Math is LaTeX, and Typst is one call away.

Coming from HTML slide frameworks

The catchFull control, paid for in nested markup on every slide, and a PowerPoint for a colleague means starting over.

With FrameSeqA linear script with no nesting, and one command each for PDF, editable PPTX, and Typst source.

FrameSeq Studio

Every gesture is an edit to the source.

Slides, source, preview, and problems in one window. It ships with the package: no editor, extension, or account to set up.

⌥

Click through to the code

Alt-click any object in the preview to put the cursor on the command that drew it. Move the cursor, and the preview follows.

✥

Drag, and the numbers change

Move and resize placed objects in the preview. Only the digits in the source change, and Ctrl+Z puts them back.

≡

Inspect the current slide

Every object on the slide, by region, with the values its commands state. Edit a number, step it with the arrow keys, or pick a colour.

⇅

Rearrange slides like paragraphs

Drag thumbnails to reorder, or duplicate, delete, and add slides. Each is one undoable edit, comments included.

{ }

TypeScript, not a template

Completions, hover documentation, and errors read from your own tsconfig.json, so the Studio agrees with VS Code and tsc.

!

Problems as you type

TypeScript errors, layout findings, build errors, and runtime errors in one list, refreshed on every save. Click one to go to it.

AI-native authoring

An agent drafts it. The checker measures it. You finish it.

A linear DSL with a small, regular API gives a model few ways to write tangled markup, and the result stays readable enough for you to take over.

  1. DraftPoint an agent at llms.txt; it writes a plain slides.ts.
  2. Checkframeseq check --json measures the rendered slides and names each overflow, clipped line, and undersized font by object.
  3. FinishKeep the Studio open beside the agent. It reloads when the file changes, and you polish by hand.

Get started

Three steps from an empty folder to your first slides.

A current Node.js LTS is all you need. The project comes with a theme, reusable components, and scripts for every export.

  1. 01

    Create

    npm create frameseq@latest my-talk
cd my-talk
npm install
  2. 02

    Write

    npm run studio

    Opens the Studio on slides.ts. Prefer your editor? npm run dev serves the preview alone.

  3. 03

    Ship

    npm run check
npm run pdf
npm run pptx

    Or npm run build for a static site to deploy anywhere.
